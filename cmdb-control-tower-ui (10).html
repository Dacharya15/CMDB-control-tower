AI Control Tower (AICT) — a centralized command platform that lets an organisation govern, manage, secure and realise value from any AI agent, model or workflow, whether native to ServiceNow or built by a third party. Built on the same unified data architecture as the CMDB, so AI initiatives connect to core business services and technology. OFFICIAL Source: AICT with CSDM 5 White Paper.

Why AICT existsstrategic value
The problemAs AI adoption scales, governance, transparency and accountability lag. Without a structured governance framework, AI initiatives expose the enterprise to compliance gaps, operational inefficiency and strategic misalignment. The answerTurn oversight into a driver of innovation rather than a brake — a single place to see every agent, model and workflow. ComplianceAICT aligns with ISO/IEC 42001:2023 and the EU AI Act to support responsible AI governance. Why it fits hereIt runs on the same data architecture as the CMDB — so AI assets are governed as rigorously as infrastructure, which is exactly what the AICT extension in this programme set out to do.

The four gaps — and what closes each
Gap · item 3CMDB Health dashboard enabled. The programme assumes it is on. Close it by adding an activation check — a dashboard that was never switched on returns nothing, and an empty result reads as "healthy" if nobody distinguishes the two states. Gap · item 13Discovery choice list for valid source. No metric covers discovery source validity. Close it with a source-register check: every writer to the CMDB should appear on the approved-source list. Gap · item 19Integration sources / CI types. A source inventory is a design artefact rather than a health metric. Close it as a one-off register, then track drift against it. Gap · item 20Mandatory fields per table. A policy decision with no platform metric. Close it by defining the mandatory set per class, then measuring conformance through the existing completeness dimension.
Structural finding — the Questionnaire sheet
What it is41 questions on environment sizing and discovery scoping: server counts by OS, storage and network device counts, environments, IP range design, database and application inventory, integrations, views, reports and user access. Why it is a gapIt asks what exists in the estate, not how healthy the data is about it. This assessment measures the second. Answering these 41 questions requires a discovery scoping exercise, which is a different activity. RecommendationKeep them separate and label them clearly. Presenting a health score as if it answered a scoping questionnaire is how a customer comes away believing coverage was assessed when only quality was.
Items 17, 18 and 20 on the Assessment guide sheet also point at MID server and credential diagnostics rather than data health — a third category: platform-operations checks.

Scoring rules — stated explicitly
Instance questionsWorth the measured compliance value from the instance (0–100). These are largely configuration-presence checks, so they score either very high or very low — there is little middle ground in "is this configured". Customer YES100 — capability exists and is practised Customer PARTIAL50 — exists in some form, inconsistently applied Customer NO0 — absent Customer N/AExcluded from numerator and denominator — not counted against the score UnansweredExcluded from the score, but reduces coverage — so a partial response cannot inflate the result CombinedWeighted mean of all scored questions in the phase, weighted by question count. Instance and customer questions carry the same weight per question. Bands0–25 Initial · 26–50 Developing · 51–75 Defined · 76–90 Managed · 91–100 Optimising — a programme-local scale, not ServiceNow's adoption stages
Read this before quoting the number
The instance floor is highInstance-only maturity lands at 92.8. That is expected and important: 26 of the 28 instance questions are configuration-presence checks, and a capability that is switched on scores 100 whether or not anyone uses it well. So the customer half is where the spread isGovernance, training, sponsorship and resourcing are where real programmes differ. A blended score that ignores the customer contribution will read as "Optimising" almost regardless of practice. Coverage gates the headlineThe combined score is only shown as final once coverage passes 80%. Below that it is labelled provisional — a score from a third of the answers is not a maturity assessment. Two low instance scores to watchCertification tasks 50 (12 tasks, 6 open) and CMDB baseline 67 (3 baselines, 2 current) are the genuine weak spots the instance reveals.
